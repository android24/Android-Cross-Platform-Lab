本节建立 Android 原生版本的性能基准。后续跨平台方案的性能比较，都应该尽量使用同一设备、同一数据、同一操作路径和同一记录口径。

## 基准指标

| 指标 | 说明 |
| --- | --- |
| 冷启动时间 | 从点击图标到首页可交互 |
| 热启动时间 | 从后台返回到首页可交互 |
| 首页首屏时间 | 目录和详情都可见 |
| 内存占用 | 首页稳定后、长列表滚动后分别记录 |
| 帧率 | 详情页滚动、搜索结果滚动、车辆数据刷新 |
| 包体积 | Debug、Release、AAB 体积 |
| 图片加载耗时 | 首次加载与缓存命中 |
| 原生调用耗时 | 文件、相机、通知、车辆数据调用边界 |

## 记录文件

性能数据写入：

```text
benchmarks/startup.md
benchmarks/memory.md
benchmarks/fps.md
benchmarks/package-size.md
benchmarks/engineering-cost.md
benchmarks/native-android-sample.md
```

`native-android-sample.md` 是填写样例，不代表真实性能结论。

## 测试原则

- 记录设备型号和 Android 版本。
- 记录 Debug 或 Release。
- 记录 Git Commit。
- 同一指标至少重复 3 次。
- 说明是否使用缓存、是否首次安装、是否清理后台。
- 只比较同一功能范围内的数据。

## 实验任务

1. 记录一次冷启动或首页首屏时间。
2. 记录一次首页稳定内存。
3. 可选记录详情页滚动帧率。
4. 可选记录 Debug/Release 包体积。
5. 写出一段原生基准观察，说明哪些数据可用于后续比较。

## 完成后复盘

- 至少有一项真实性能记录。
- 记录包含设备、系统、构建类型、测试步骤和结果。
- 能说明数据限制，例如 Debug 包、模拟器、未开启混淆等。
- 能指出后续跨平台版本必须保持一致的测试路径。
