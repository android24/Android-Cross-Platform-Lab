> [!CAUTION]
> ⚠️ Alpha内测版本警告：此为早期内部构建版本，课程文档、实验工程和评测口径仍在持续完善，欢迎大家提Issue反馈问题或建议。

> [!WARNING]

本节建立 Android 原生版本的性能基准。后续跨平台方案的性能比较，都应该尽量使用同一设备、同一数据、同一操作路径和同一记录口径。

## 本节产物

完成本节后，课程应该拿到第一份可对照的 Android 原生性能记录：

- 至少记录一次启动时间或首页稳定内存。
- 记录设备、系统版本、构建类型、测试步骤和结果。
- 写明当前功能范围，避免后续拿不等价功能做比较。
- 为 Web/PWA、Hybrid、RN、Flutter、KMP 留下相同测试路径。

## 基准指标

| 指标 | 说明 |
| --- | --- |
| 冷启动时间 | 从点击图标到首页可交互 |
| 热启动时间 | 从后台返回到首页可交互 |
| 首页首屏时间 | 目录和详情都可见 |
| 内存占用 | 首页稳定后、长列表滚动后分别记录 |
| 帧率 | 详情页滚动、搜索结果滚动、车辆数据刷新 |
| 包体积 | Debug、Release、AAB 体积 |
| 图片加载耗时 | 首次加载与缓存命中 |
| 原生调用耗时 | 文件、相机、通知、车辆数据调用边界 |

## 记录文件

性能数据写入：

```text
benchmarks/startup.md
benchmarks/memory.md
benchmarks/fps.md
benchmarks/package-size.md
benchmarks/engineering-cost.md
benchmarks/native-android-sample.md
```

`native-android-sample.md` 是填写样例，不代表真实性能结论。

## 测试原则

- 记录设备型号和 Android 版本。
- 记录 Debug 或 Release。
- 记录 Git Commit。
- 同一指标至少重复 3 次。
- 说明是否使用缓存、是否首次安装、是否清理后台。
- 只比较同一功能范围内的数据。

## 推荐测试路径

不同技术栈都尽量复用下面几条路径：

| 路径 | 操作 | 观察点 |
| --- | --- | --- |
| 启动路径 | 清理后台后点击图标进入首页 | 冷启动、首屏可交互 |
| 目录路径 | 首页连续切换 10 个目录项 | 状态更新、重组、卡顿 |
| 详情路径 | 打开长文章并上下滚动 | 帧率、图片加载 |
| 搜索路径 | 输入关键词并打开结果 | 搜索耗时、列表滚动 |
| 车辆路径 | 进入车辆状态页停留 30 秒 | 周期刷新、内存变化 |
| 原生能力路径 | 触发通知、文件或相机 | 调用耗时、权限处理 |

## 记录模板

```text
技术栈：Android Native
设备：
系统版本：
构建类型：Debug / Release
Git Commit：
测试日期：
功能范围：
测试路径：
重复次数：
结果：
观察：
限制：
```

如果暂时只有模拟器，也可以先记录模拟器数据，但必须写清楚“不能代表真实设备性能”。性能课的核心不是制造漂亮数字，而是训练同口径比较。

## 动手路径

1. 在 `benchmarks/startup.md` 中补一条启动记录。
2. 在 `benchmarks/memory.md` 中补一条首页稳定内存记录。
3. 如条件允许，用 Android Studio Profiler、Macrobenchmark、Perfetto 或 `adb shell dumpsys` 收集补充数据。
4. 把功能范围写清楚，例如“仅目录、详情、搜索、车辆状态，无真实网络请求”。
5. 在记录中写出当前限制，供后续跨平台版本比较时引用。

## 实验任务

1. 记录一次冷启动或首页首屏时间。
2. 记录一次首页稳定内存。
3. 可选记录详情页滚动帧率。
4. 可选记录 Debug/Release 包体积。
5. 写出一段原生基准观察，说明哪些数据可用于后续比较。

## 完成后复盘

- 至少有一项真实性能记录。
- 记录包含设备、系统、构建类型、测试步骤和结果。
- 能说明数据限制，例如 Debug 包、模拟器、未开启混淆等。
- 能指出后续跨平台版本必须保持一致的测试路径。
