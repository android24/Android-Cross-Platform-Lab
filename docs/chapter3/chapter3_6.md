本节实现原生基准中的本地缓存能力。缓存不仅用于提升体验，也用于后续和 PWA、Hybrid 离线包、RN/Flutter 本地存储、KMP 数据库方案进行比较。

## 本节产物

完成本节后，应用应至少具备一种可观察的持久化能力：

- 收藏或浏览历史在应用重启后仍存在。
- 离线模式开关状态可以保存。
- Repository 对外暴露统一数据接口，UI 不直接操作存储实现。
- 文档中记录当前使用 DataStore、Room、文件缓存或图片库缓存的理由。

## 缓存范围

| 能力 | 阶段 | 说明 |
| --- | --- | --- |
| 收藏 | 核心/增强 | 保存用户收藏条目 |
| 浏览历史 | 增强 | 保存最近浏览文章 |
| 搜索历史 | 增强 | 保存最近搜索词 |
| 手册数据缓存 | 增强 | 支持离线浏览已缓存内容 |
| 图片缓存 | 增强 | 支持离线展示已缓存图片 |
| 设置缓存 | 增强 | 主题、语言、离线模式 |

## 存储选择

| 数据类型 | 可选方案 |
| --- | --- |
| 简单设置 | DataStore |
| 收藏、历史、搜索词 | Room 或 DataStore |
| 手册数据缓存 | Room、文件缓存或预置 assets |
| 图片缓存 | 图片库缓存或自定义文件缓存 |

课程中不强制唯一方案，但要记录选择理由，因为后续跨平台技术栈的本地存储能力差异很大。

## 推荐最小方案

第一版可以先用 DataStore 保存轻量状态：

| 数据 | 推荐第一版方案 | 后续可替换方向 |
| --- | --- | --- |
| 收藏 ID 集合 | DataStore | Room 或 KMP 数据库 |
| 搜索历史 | DataStore | Room |
| 离线模式 | DataStore | 保持 DataStore |
| 手册 JSON | assets 预置 | Room、文件缓存、网络同步 |
| 图片 | Coil 默认缓存 | 自定义文件缓存或离线资源包 |

这样学习者可以先看到“持久化生效”的体验，再把存储选择和跨平台差异放到后续章节比较。

## 离线模式

离线模式至少要明确：

- 离线开关状态是否可见。
- 离线时是否仍能浏览已缓存内容。
- 未缓存内容如何提示。
- 图片加载失败是否会导致白屏。

## 缓存边界

```text
Composable
    只展示收藏、历史、离线状态
ViewModel
    处理用户事件，组合 Repository 数据
Repository
    读写 DataStore、Room、文件缓存或图片缓存
Storage
    平台相关实现，不暴露给 UI
```

缓存实验的重点是边界清晰。后续 PWA 会使用 Service Worker，RN/Flutter 会使用插件或平台数据库，KMP 会尝试共享部分数据逻辑。原生基准必须先说清楚自己缓存了什么、没有缓存什么。

## 动手路径

1. 选择收藏或浏览历史作为第一项持久化能力。
2. 使用 DataStore 保存收藏 ID 集合或最近浏览文章 ID。
3. ViewModel 订阅收藏/历史变化，并更新页面状态。
4. 在详情页增加收藏按钮或历史记录触发点。
5. 增加离线模式开关，先保存开关状态。
6. 记录当前哪些数据仍然来自 assets，哪些数据已经持久化。

## 实验任务

1. 实现收藏和取消收藏的持久化。
2. 实现浏览历史或搜索历史。
3. 为手册数据或图片预留缓存策略。
4. 增加离线模式开关。
5. 记录当前缓存方案和限制。

## 阶段挑战

- 应用重启后，收藏按钮状态保持正确。
- 收藏列表和详情页使用同一份收藏数据源。
- 打开离线模式后，页面顶部或设置页能清晰显示当前状态。

## 完成后复盘

- 应用重启后收藏或历史仍存在。
- 删除或取消收藏后 UI 及时刷新。
- 离线模式下核心浏览流程不依赖真实网络。
- 未缓存内容有明确提示。

- RN/Flutter 的本地数据库和原生 Room 相比成本如何。
- KMP 是否适合共享缓存策略和 Repository。
