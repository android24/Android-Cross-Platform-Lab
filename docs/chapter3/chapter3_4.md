本节目标是完成原生 P0 中最重要的可视化体验：目录、详情、搜索和车辆状态。它会成为后续跨平台 UI 方案的视觉和交互基准。

## 页面范围

| 页面 | P0 要求 |
| --- | --- |
| 首页/目录页 | 横屏左右分栏，左侧目录，右侧默认选中第一篇文章 |
| 手册详情页 | 展示标题、摘要、正文段落、图片占位和收藏按钮 |
| 搜索页 | 输入关键词，展示结果列表，点击进入详情 |
| 车辆状态页 | 展示电量、续航、胎压、车门、空调和车速 |
| 原生能力页 | 至少提供一个能力入口 |

## 布局要求

智能座舱场景优先考虑横屏，但普通手机也要可用：

| 宽度 | 建议布局 |
| --- | --- |
| 小于 600dp | 单列布局，目录可折叠 |
| 600dp 到 960dp | 主从分区，目录较窄 |
| 大于 960dp | 稳定左右分栏，详情区展示更多信息 |

核心要求是：文本、按钮、图片和列表不重叠，横屏下主要操作不依赖过深层级。

## 状态设计

可以先用简单状态模型：

```text
ManualUiState
  Loading
  Content(categories, selectedArticle, favoriteIds)
  Empty
  Error(message)

SearchUiState
  query
  results
  recentQueries
  isSearching
```

车辆状态建议单独建模，避免和手册页面状态混在一起。

## 任务步骤

1. 实现目录列表，并支持选中态。
2. 实现右侧详情区域，展示标题、摘要、正文和图片占位。
3. 实现搜索输入、搜索结果、空状态和点击跳转。
4. 实现车辆状态页，展示电量、续航、胎压、车门、空调和车速。
5. 在横屏和平板宽度下检查布局是否稳定。

## 验收标准

- 横屏下目录和详情不重叠。
- 小屏下可以退化为单列或抽屉。
- 搜索空结果有明确提示。
- 车辆状态刷新不阻塞 UI。
- UI 状态变化不会导致页面明显闪烁或丢失选中态。
