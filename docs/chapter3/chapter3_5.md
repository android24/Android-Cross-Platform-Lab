本节完成原生 P0 的最后一块：接入至少一个 Android 原生能力，并形成第一份可复查的性能记录。后续 Hybrid、RN、Flutter 都会围绕这一节比较桥接成本和性能差异。

## 原生能力范围

P0 阶段任选一项即可：

| 能力 | 最小要求 | 对照意义 |
| --- | --- | --- |
| 通知 | 请求权限，发送一条车辆提醒通知 | 后续对比 Hybrid Bridge、RN Module、Flutter Channel |
| 文件选择 | 打开系统文件选择器，展示文件名和 MIME 类型 | 对比系统 Intent 与跨平台封装成本 |
| 相机 | 调用相机或相册，展示图片预览 | 对比权限、生命周期和结果回调 |

P1 阶段再补齐三项能力。

## 失败场景

原生能力实验不能只验证“成功路径”，至少要处理：

- 用户取消文件选择或拍照。
- 用户拒绝权限。
- 系统能力不可用。
- 页面切到后台或 Activity 重建。

这些失败场景后续进入跨平台框架时，通常会变成 Bridge、Module、Channel 的错误处理边界。

## 性能记录范围

P0 至少完成一项记录：

| 指标 | 记录位置 |
| --- | --- |
| 冷启动时间 | `benchmarks/startup.md` |
| 首页稳定内存 | `benchmarks/memory.md` |
| 详情页滚动帧率 | `benchmarks/fps.md` |
| Debug/Release 包体积 | `benchmarks/package-size.md` |

可以参考 `benchmarks/native-android-sample.md` 的结构填写。

## 任务步骤

1. 在原生能力页中完成通知、文件选择或相机中的一个能力闭环。
2. 处理权限拒绝、用户取消和系统能力不可用。
3. 记录设备型号、系统版本、构建类型和 Git Commit。
4. 采集至少一次启动、内存、帧率或包体积数据。
5. 在 `benchmarks/native-android-sample.md` 中复制一份记录结构，并替换为真实数据。

## 验收标准

- 权限拒绝或用户取消时应用不崩溃。
- 原生能力调用有成功、失败和降级提示。
- 性能记录包含测试环境、测试步骤、结果和观察。
- 能指出本次数据是否可与后续跨平台版本直接比较。
